# Rep Counter

เครื่องนับจำนวนครั้งการยกน้ำหนัก ที่ไม่ได้นับแค่ขึ้น-ลง แต่ตรวจสอบคุณภาพของการยกด้วย
ถ้ายกไม่สุดช่วงจะไม่นับให้ และถ้าความเร็วในการยกตกลงจนเข้าข่ายกล้ามเนื้อล้า ระบบจะเตือน

**สถานะปัจจุบัน:** ใช้ Potentiometer บนชิลด์จำลองมุมข้อศอกระหว่างรอเซนเซอร์ MPU6050
โครงสร้างซอฟต์แวร์แยกชั้นไว้แล้ว เมื่อได้เซนเซอร์จริงจะแก้เพียงฟังก์ชันเดียว

---

## 1. อุปกรณ์ที่ใช้

| รายการ | หมายเหตุ |
|---|---|
| STM32 Nucleo-F411RE | บอร์ดหลัก |
| STEO Training Shield 1 Rev 02.00 | LED 4 ดวง, สวิตช์ 4 ตัว, 7-Segment, Potentiometer |
| จอ OLED SSD1306 0.96 นิ้ว I2C | ต่อเพิ่มภายนอก ~75 บาท |
| สาย USB | จ่ายไฟและใช้เป็นช่อง UART ไปยังคอม |

| ขาบนจอ OLED | ต่อไปที่ |

| SDA | **PB9** (I2C1_SDA) |

| Potentiometer | PA4 | ADC1 ช่อง 4 ใช้จำลองมุมแขน |

| สวิตช์ D3 | PB3 | กลับหน้าภาพรวม |

| UART | PA2, PA3 | ผ่าน ST-Link Virtual COM |

## 2. วิธีใช้งาน

1. Build และ Flash ลงบอร์ด
2. เปิด Terminal ที่ **115200 8N1** (แนะนำ serialterminal.com บน Chrome หรือ Edge)
3. หมุน Potentiometer ไปทางซ้ายสุด = แขนอยู่ล่าง (0 องศา)
4. กดปุ่ม **D2** เริ่มเซ็ต — ไฟเขียวติด จอขึ้น SET RUNNING
5. หมุนขึ้นจนสุดแล้วกลับลงสุด = นับ 1 ครั้ง
6. กด **D2** อีกครั้งเพื่อจบเซ็ต — จอแสดงผลสรุป
7. กด **D4** ดูรายละเอียดทีละหน้า กด **D3** กลับหน้าภาพรวม

### เกณฑ์การนับ

| เงื่อนไข | ผลลัพธ์ |
|---|---|
| ยกขึ้นเกิน 130 องศา แล้วกลับลงต่ำกว่า 40 องศา | นับ 1 ครั้ง |
| ยกขึ้นไม่ถึง 130 องศา แล้วกลับลง | รายงาน PARTIAL ไม่นับ |
| ช่วงการเคลื่อนไหวน้อยกว่า 30 องศา | ถือว่าเป็นการสั่น ไม่รายงาน |
| ความเร็วตกต่ำกว่า 80% ของครั้งแรก | ติดธง FATIGUE |

## 3. การแสดงผล

### LED 4 ดวง

ไฟเขียวเป็นไฟบอกสถานะ อีก 3 ดวงเป็นแถบระดับความสูงที่ยกได้

| สถานการณ์ | เขียว | เหลือง | แดง | น้ำเงิน |
|---|---|---|---|---|
| ยังไม่เริ่ม / กดจบแล้ว | ดับ | ดับ | ดับ | ดับ |
| เริ่มเซ็ต แขนอยู่ล่าง | ติด | ดับ | ดับ | ดับ |
| ยกถึง 45 องศา | ติด | ติด | ดับ | ดับ |
| ยกถึง 90 องศา | ติด | ติด | ติด | ดับ |
| ยกถึง 130 องศา = ยกสุด | ติด | ติด | ติด | ติด |

แถบระดับใช้หลัก **ค้างค่าสูงสุด** คือตอนลดแขนลงไฟจะไม่ดับตาม แต่ค้างบอกว่าครั้งนั้น
ยกได้ถึงระดับไหน แล้วรีเซ็ตเมื่อลดแขนต่ำกว่า 25 องศาเพื่อเริ่มครั้งใหม่

### 7-Segment

แสดงจำนวนครั้งที่นับได้แบบเรียลไทม์ ถ้าเกิน 9 จะสลับหลักสิบกับหลักหน่วยอัตโนมัติ
(แสดงหลักละ 0.7 วินาที เว้นว่าง 0.2 วินาที) เพราะจอมีเพียงหลักเดียว

### จอ OLED

จอถูกวาดใหม่เฉพาะตอนเปลี่ยนสถานะ ไม่วาดทุกรอบของ main loop เพื่อไม่ให้กระทบการจับเวลา

**ตอนเปิดเครื่อง**
```
YOK HAI SUD
FULL RANGE COUNT

PRESS D2 TO START
```

**ระหว่างเซ็ต** — ค้างไว้ตลอด ข้อมูลสดดูจาก LED และ 7-Segment
```
SET RUNNING
COUNT ON 7SEG
HEIGHT ON 3 LEDS
LIFT NOW
PRESS D2 TO END
```

**หลังกดจบเซ็ต** มี 6 หน้า

| หน้า | เนื้อหา | ปุ่ม |
|---|---|---|
| ภาพรวม | REPS / PARTIAL / FATIGUE | D3 กลับมาหน้านี้ได้เสมอ |
| 1 | RANGE OF MOTION — min avg max หน่วยองศา | D4 ไปหน้าถัดไป |
| 2 | LIFT UP TIME — min avg max หน่วยวินาที | D4 |
| 3 | LOWER DOWN TIME — min avg max หน่วยวินาที | D4 |
| 4 | LIFT SPEED — min avg max หน่วยองศาต่อวินาที | D4 |
| 5 | SPEED DROP — LAST / WORST / TIRED | D4 วนกลับหน้า 1 |

ค่าสถิติคิดจากเฉพาะครั้งที่นับสำเร็จ ครั้งที่ยกไม่สุดไม่ถูกนำมาคำนวณ

### UART

ส่งข้อมูลออกเป็น CSV ระหว่างเซ็ต และสรุปตอนจบ

```
SET START,rep,rom,up_ms,down_ms,speed,fatigue
REP,1,rom=160,up=330,down=1150,speed=484
REP,2,rom=160,up=390,down=1300,speed=410
PARTIAL,1,rom=90,up=1360,down=0,speed=66
REP,3,rom=160,up=620,down=1790,speed=258,FATIGUE
SET END,total=3,partial=1,fatigue=1
```

| ตัวย่อ | ความหมาย | หน่วย |
|---|---|---|
| `rep` | repetition = ลำดับครั้งที่ยก | ครั้ง |
| `rom` | Range Of Motion = ช่วงการเคลื่อนไหว | องศา |
| `up_ms` | เวลาช่วงยกขึ้น (concentric) | มิลลิวินาที |
| `down_ms` | เวลาช่วงลดลง (eccentric) | มิลลิวินาที |
| `speed` | ความเร็วในการยก | องศาต่อวินาที |
| `fatigue` | จำนวนครั้งที่ตรวจพบความล้า | ครั้ง |

## 4. โครงสร้างซอฟต์แวร์

```
Inc/
  drv_gpio.h      ขา analog และขา UART
  drv_tim.h       TIM2 = ตัวกระตุ้น ADC 100 Hz, TIM3 = นาฬิกา 1 ms
  drv_adc.h       ADC1 + DMA2 Stream0 (ไม่มี polling)
  drv_uart.h      USART2 + DMA1 Stream6 (ไม่มี polling)
  drv_exti.h      External Interrupt ของสวิตช์ 4 ตัว
  drv_seg7.h      7-Segment ผ่าน BCD decoder
  drv_led.h       LED 4 ดวงบนชิลด์
  drv_i2c.h       I2C1 ที่ 100 kHz
  drv_oled.h      SSD1306 128x64 พร้อมตารางฟอนต์ 5x7
  app_repcount.h  อัลกอริทึมนับครั้งและสถิติ
  app_report.h    จัดรูปแบบข้อความส่ง UART
  app_display.h   ตัดสินใจว่าจะแสดงอะไรบนจอทั้งสามชนิด
Src/
  (ไฟล์ .c ของทุกโมดูลข้างบน)
  main.c          เรียกใช้ทุกโมดูล ไม่มี logic ซับซ้อนอยู่ในนี้
```

**หลักการแบ่งชั้น**

- ชั้น Driver แตะ register ได้เท่านั้น ไม่รู้จักเรื่องการยกน้ำหนักเลย
- ชั้น Application ไม่แตะ register แม้แต่บรรทัดเดียว
- `app_repcount.c` ไม่รู้ว่าข้อมูลมุมมาจากไหน จึงใช้ได้ทั้งกับ Potentiometer และเซนเซอร์จริง
- ISR ทำงานสั้นที่สุด เพียงเคลียร์ธง เก็บค่า แล้วยกธงบอก main loop

## 5. Peripheral และ Interrupt

| Peripheral | ใช้ทำอะไร | Interrupt |
|---|---|---|
| GPIO | LED, 7-Segment, ขาอินพุต | — |
| ADC1 + DMA2 Stream0 | อ่านมุมแขน 100 ครั้งต่อวินาที | `DMA2_Stream0_IRQHandler` |
| USART2 + DMA1 Stream6 | ส่งข้อมูล CSV ไปคอม | `DMA1_Stream6_IRQHandler` |
| EXTI + SYSCFG | สวิตช์ 4 ตัว 4 vector | `EXTI15_10`, `EXTI3`, `EXTI9_5`, `EXTI4` |
| TIM2 | สร้าง TRGO 100 Hz กระตุ้น ADC ด้วยฮาร์ดแวร์ล้วน | — |
| TIM3 | นาฬิกา 1 ms สำหรับจับจังหวะการยก | `TIM3_IRQHandler` |
| I2C1 | คุยกับจอ OLED | — |

รวม **7 แหล่ง interrupt**

### ลำดับความสำคัญ

| ลำดับ | Interrupt | เหตุผล |
|---|---|---|
| 0 สูงสุด | TIM3 นาฬิกา 1 ms | ถ้าเวลาเพี้ยน ค่าที่คำนวณทั้งหมดเพี้ยนตาม |
| 1 | EXTI ของสวิตช์ | ต้องตอบสนองผู้ใช้ทันที |
| 2 | DMA ของ ADC | ข้อมูลถูกเก็บโดยฮาร์ดแวร์อยู่แล้ว รอได้ |
| 3 ต่ำสุด | DMA ของ UART | แค่แจ้งว่าส่งเสร็จ ไม่กระทบการวัด |

### ตรงตาม Requirement ของวิชา

| ข้อ | เกณฑ์ | ทำอย่างไร |
|---|---|---|
| 1 | GPIO เป็น Input หรือ Output | LED 4 ดวง, 7-Segment, สวิตช์ |
| 2 | UART ใช้ Interrupt หรือ DMA ห้าม polling | DMA1 Stream6 + interrupt แจ้งเมื่อส่งจบ |
| 3 | ADC ใช้ Interrupt หรือ DMA ห้าม polling | TIM2 TRGO กระตุ้น + DMA2 Stream0 วนเก็บ |
| 4 | ใช้ EXTI อย่างน้อย 1 จุด | ใช้ 4 จุด บน 4 vector |
| 5 | Peripheral เสริมอย่างน้อย 1 รายการ | I2C และ Timer |

## 6. หมายเหตุทางเทคนิค

**ไม่ใช้ `sprintf`** เพราะทำให้เกิด HardFault จาก heap ไม่พอ จึงเขียนฟังก์ชันแปลงเลข
เป็นข้อความเอง และแปลงเวลาเป็นวินาทีด้วยเลขจำนวนเต็มล้วน ไม่ใช้ float

**เคลียร์ `EXTI->PR` ด้วย `=` ไม่ใช่ `|=`** เพื่อไม่ให้ไปล้างเส้นอื่นที่อยู่ใน vector เดียวกัน

**I2C รอให้บัสว่างก่อนเริ่มทุกเฟรม** ถ้าสั่ง START ทันทีหลัง STOP ข้อมูลที่จอได้รับจะเพี้ยน

**ส่งภาพเข้าจอทีละหน้า** 8 ครั้ง ครั้งละ 128 ไบต์ แต่ละหน้ามีคำสั่งบอกตำแหน่งของตัวเอง
ทำให้ไม่มีการเลื่อนสะสมถ้าก้อนใดก้อนหนึ่งพลาด

**ทุกจุดที่รอสัญญาณ I2C มี timeout** ถ้าไม่ได้ต่อจอ โปรแกรมจะไม่ค้าง การนับและ UART
ยังทำงานปกติ

### การตั้งค่าโปรเจคใน STM32CubeIDE

ต้องเพิ่ม symbol **`STM32F411xE`** ที่ Project Properties → C/C++ General →
Paths and Symbols → แท็บ **Symbols** → GNU C → Add
(ค่าเริ่มต้น `STM32F411RETx` ที่ IDE ใส่มาให้ CMSIS ไม่รู้จัก จะขึ้น `#error` ทันที)

### ปรับแต่งที่อาจต้องทำ

| อาการ | แก้ที่ไหน |
|---|---|
| จอไม่ติดเลย | เปลี่ยน `OLED_ADDRESS` ใน `drv_oled.c` จาก `0x3Cu` เป็น `0x3Du` |
| ตัวอักษรริมซ้ายโดนตัด | เปลี่ยน `OLED_COLUMN_OFFSET` ใน `drv_oled.c` เป็น `2u` |
| อยากให้จอวาดเร็วขึ้น | `I2C_CCR_STANDARD_100K` เป็น `14u`, `I2C_TRISE_STANDARD` เป็น `5u` และเติม `I2C_CCR_FS \|` หน้าค่า CCR |
| ปุ่มทำงานสวนทาง | สลับ `FTSR` กับ `RTSR` ใน `v_extiEnableLine()` ของ `drv_exti.c` |
| Potentiometer อยู่ที่ PB1 | `GPIO_ANALOG_PIN` เป็น `1u` และเปลี่ยนพอร์ตเป็น GPIOB ใน `drv_gpio.c`, `ADC_CHANNEL_NUMBER` เป็น `9u` และ `ADC_SMPR2_SHIFT_CH4` เป็น `27u` ใน `drv_adc.c` |

## 7. ขั้นถัดไปเมื่อได้เซนเซอร์ MPU6050

1. เพิ่ม `drv_mpu6050.c/.h` ใช้ `drv_i2c` ที่มีอยู่แล้ว (ที่อยู่ 0x68 บนบัสเดียวกับจอ)
2. อ่านค่า 14 ไบต์ แล้วรวมค่าจาก accelerometer กับ gyroscope ด้วย complementary filter
3. แก้ `u2_mainReadAngle()` ใน `main.c` ที่คอมเมนต์ว่า `SENSOR SOURCE` ให้เรียกเซนเซอร์แทน ADC
4. Potentiometer เปลี่ยนหน้าที่เป็นตัวตั้งจำนวนครั้งเป้าหมาย

`app_repcount.c`, `app_report.c` และ `app_display.c` **ไม่ต้องแก้แม้แต่บรรทัดเดียว**
จุดนี้คือสิ่งที่ควรพูดตอนนำเสนอเรื่อง Software Structure
